# 项目架构与死代码清理评审

## Goal

降低 Gala 当前桌面照片应用的维护成本和架构漂移风险，在保持现有用户行为的前提下，找出高可信死代码、重复适配层和边界混乱点，先完成一批可验证的安全整理，再留下分阶段后续计划。

## Background / Confirmed Facts

- 项目是 React/Vite 前端 + Tauri/Rust 后端的单仓库，前端入口、状态、desktop bridge、features、components 和 domain 已有目录划分；Rust 侧主要分为 `library` 与 `capability` 两组模块。
- 工作区当前有大量未提交改动（约 74 个已修改/新增路径），评审和实现必须避免覆盖或回退这些已有改动。
- `npm run build` 已通过；Vitest 当前 25 个测试文件、118 个测试全部通过；`cargo check` 与 `cargo test --no-run` 已通过。
- 现有规范索引仍是模板状态，目录结构、质量、状态和类型约定未被真实代码填充，导致后续重构缺少可执行边界。
- 初步扫描发现若干需要核实的整理信号：前端 desktop bridge 中大量重复的 Tauri 调用/错误日志包装；`ComingSoonView` 与已存在 feature 页面并存；Rust 中存在 `#[allow(dead_code)]`；仓库包含多个历史计划文档和临时测试脚本；这些信号不能仅凭名称直接删除，必须结合引用和运行路径验证。

## Requirements

1. 对前端、Rust 后端、测试、脚本和文档做一次基于引用关系与构建结果的结构审查，输出按置信度和风险分级的发现。
2. 明确区分“已证实未使用”“疑似重复但仍有运行路径”“暂不处理的历史/实验代码”，避免把未提交工作或未来入口误删。
3. 在用户确认的范围内，实施一批不改变产品行为的高价值整理：删除已证实死代码，合并安全的重复包装，收敛目录/命名，补足必要测试或质量门槛。
4. 为后续较大架构调整留下设计边界、迁移顺序、回滚点和暂缓项；不把大规模功能重写混入本次清理。
5. 保护现有未提交改动：修改前记录基线，按文件核对 diff，禁止使用会覆盖工作区的 reset、checkout 或整体 stash 操作。

## Scope

### In scope

- `src/`、`src-tauri/src/`、对应测试、构建脚本和与当前架构直接相关的文档。
- 可通过静态引用、编译器/测试、运行入口和人工核对证实的死代码及重复代码。
- 规范文档中与实际项目一致的最小补充，使后续整理有明确约束。

### Out of scope

- 改变照片库数据模型、扫描语义、相似度/视觉算法或用户导航信息架构。
- 大规模引入新的状态管理、依赖或跨平台算法框架。
- 未经单独设计和验收的数据库迁移、性能重写、UI redesign 或删除仍可能被外部调用的公开入口。

## Acceptance Criteria

- [x] 有一份带文件路径/符号、证据、风险等级和建议动作的审查结果，覆盖前端、Rust、测试/脚本、文档四类对象。
- [x] 所有拟删除代码都有至少两类证据（引用搜索 + 编译/测试/入口核验），且与当前未提交 diff 分离核对。
- [x] 完成的整理通过 `npm run test`、`npm run build`、`cargo check --manifest-path src-tauri/Cargo.toml` 和适用的 Rust 测试。
- [x] 代码改动前后行为测试保持通过；新增测试只覆盖真实回归风险，不为实现细节堆砌测试。
- [x] 形成后续架构优化清单，标注优先级、依赖、风险和是否需要单独任务；未完成项不会被伪装成已清理。
- [x] 最终工作区不包含本次验证产生的临时测试数据、临时截图或其他用户态产物。

## Confirmed scope decision

用户已确认首轮按“行为保持的安全清理”执行：优先处理已证实死代码、安全的重复 bridge 和规范补齐；涉及数据模型、算法或 UI 行为的架构重构拆为后续任务。验收以现有功能和质量门槛保持通过为准。
