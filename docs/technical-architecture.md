# Product Technical Architecture

> 顶层架构总纲。只回答：产品分哪些层、层间如何协作、不同组合能形成什么形态的产品。
> 数据结构、控制流、UI、算法等细节在 [README.md](README.md) 指向的相应文档。

## 一句话结论

Gala 的架构不是围绕单个页面或单个 feature 组织，而是围绕五个可独立、可组合的层次组织：前端层、数据层、控制层、算法层、AI Agent 层。

这种设计允许 Gala 从一个基础照片管理应用，逐步演进成具备跨平台算法能力和外部 AI 接入能力的新式产品。

---

## 五层总览

```text
                 +----------------------+
                 |     AI Agent Layer   |
                 | MCP / Skills / APIs  |
                 +----------+-----------+
                            |
                            v
+----------------------+    +----------------------+    +----------------------+
|     Frontend Layer   | -> |    Control Layer     | -> |      Data Layer      |
| Desktop App / Views  |    | Logic / Jobs / APIs  |    | Photos / Metadata    |
+----------------------+    +----------+-----------+    | Index / Knowledge    |
                                         |
                                         v
                              +----------------------+
                              |   Algorithm Layer    |
                              | Cross-platform Lib   |
                              +----------------------+
```

这个结构有三个关键特点：

- 前端层和 AI Agent 层都是入口，但分别服务于人类用户和外部智能系统。
- 控制层是运行时中枢，负责连接界面、数据、算法和外部调用。
- 算法层不是应用内部杂糅的一部分，而是可独立存在、可跨平台演进的能力库。

---

## 第一层：前端层

前端层负责桌面应用的页面设计、展示逻辑和用户交互体验。

它关注：

- 页面结构与导航。
- 照片浏览、筛选、管理和编辑入口。
- 状态反馈、任务可视化和交互解释。

它不直接承担数据建模、任务编排或算法实现。

---

## 第二层：数据层

数据层负责照片事实与产品知识的持久化。

它保存：

- 原始照片引用和来源关系。
- EXIF、派生元数据、索引、标签、聚类、缓存引用。
- 产品运行中沉淀出的结果、任务状态和知识结构。

数据层是 Gala 的统一事实基础。

---

## 第三层：控制层

控制层是系统的运行中枢。

它负责：

- 接收来自前端层和 AI Agent 层的请求。
- 管理扫描、导入、索引、缓存、分析等后台任务。
- 编排数据层和算法层的调用顺序。
- 对外提供稳定的应用接口与服务语义。

控制层把静态数据和底层能力转化为可运行的产品行为。

---

## 第四层：算法层

算法层负责后端需要调用的图像能力，并且应具备跨平台性。

它应被设计成可以独立存在的能力库，而不是散落在应用内部的局部函数集合。

这一层承担的能力包括：

- 图像解析与特征提取。
- 人脸、人物、场景、文本等识别能力。
- 相似图、近重复、连拍关系分析。
- 推荐、聚类、筛选等图像关系计算。

---

## 第五层：AI Agent 层

AI Agent 层不是系统本体的一部分，而是系统对外暴露给 AI 使用的接入层。

它负责把 Gala 已有的正式能力，以 AI 可理解、可调用的形式开放出去。

这一层可包括：

- MCP 接口。
- Skill 体系。
- Agent 可调用的任务入口。
- 面向外部自动化系统的能力描述。

---

## 各层的独立完整性

五层架构的核心价值之一，是每层都具备清晰边界，并且可以形成不同组合。

### 前端层 + 数据层 + 控制层

这是最小完整产品形态。

三层结合后，系统已经可以成为一个基本的照片管理 app，具备索引、浏览、管理、状态反馈和后台任务能力。

### 数据层 + 控制层 + AI Agent 层

这三层结合后，系统可以成为一个纯后端的照片 agent。

它不需要桌面界面，但仍然具备照片数据管理、任务控制和对外 AI 调用能力。

### 算法层独立存在

算法层本身应可以作为独立库存在。

它可以被 Gala 控制层调用，也可以被外部脚本、API 或其他服务直接调用。

### 前端层 + 数据层 + 控制层 + 算法层

这四层结合后，系统会成为一个具备稳定智能能力的升级版照片应用。

### 前端层 + 数据层 + 控制层 + 算法层 + AI Agent 层

这是 Gala 的完全体。

在这个形态下，系统同时具备完整的桌面体验、完整的数据与控制体系、独立的跨平台算法能力，以及标准化的 AI 接入层。

---

## 各层之间的边界原则

### 前端层与控制层

- 前端层提出请求，控制层负责执行。
- 前端层展示状态，控制层维护任务和流程语义。
- 前端层不直接操作底层数据结构或算法实现。

### 控制层与数据层

- 控制层定义读写流程和业务规则。
- 数据层保存事实与结果。
- 数据层不承载复杂产品流程判断。

### 控制层与算法层

- 控制层负责编排何时调用算法。
- 算法层负责给出分析结果。
- 算法层不承担应用级任务管理与产品状态编排。

### AI Agent 层与控制层

- AI Agent 层对外暴露的是系统能力入口。
- 控制层仍然是实际执行与状态管理中心。
- AI Agent 层不应绕过控制层直接拼接底层模块。

---

## People 与 Similar 在这套架构中的位置

`People` 和 `Similar` 都应被视为建立在系统能力之上的产品模块，而不是独立架构层。

### People

`People` 属于前端层和控制层共同组织出来的上层功能模块，其能力基础来自数据层与算法层。

### Similar

`Similar` 同样属于上层功能模块，其能力基础来自数据层、控制层和算法层的协同。

因此，`People` 和 `Similar` 是能力的消费者，是产品模块，而不是系统基础层本身。

---

## 架构演进顺序

### 第一阶段

先构建前端层、数据层和控制层，得到稳定的基础照片管理应用。

### 第二阶段

引入算法层，把系统从“管理工具”提升为“具备图像理解能力的应用”。

### 第三阶段

引入 AI Agent 层，把系统从“具备智能功能的应用”提升为“可被外部智能系统调用的平台型产品”。

每一步都能形成完整产品，同时不破坏层次的独立性。
